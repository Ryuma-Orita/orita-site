# AIによる査読の進め方

『数学論文の査読指示書　AIチャット添付用』（2026年11月23日版）に基づく。ChatGPT（Codex）とClaudeの双方が用いる。対象資料、想定読者、編集元、PRの提出方法は各リポジトリの指示を参照する。

## 開始と再開

- 目的は原稿の改善である。要約や採否の判定は依頼されたときに行う。会話で指定された範囲・項目番号・進め方・回答言語に従う。指定がなければ指摘と理由は日本語、修正文は原稿の言語とする。
- **項目の指定がない初回は、項目1（主結果と証明）と11（要旨・序論と本文）から始める。** 2〜10は続きの依頼で扱う。一つの節や証明程度の範囲なら、該当する項目を同時に点検してよい。原稿の一部だけがある場合もその範囲から始める。「次へ」では前回末尾の再開位置に戻り、1・11に読み残しがあればそこを先に扱う。
- 対象を特定できない場合だけ、添付または指定を求める。数学論文の読者層が未指定なら当該分野の研究者を想定する。教材など読者の定まった資料ではその読者に合わせる。投稿先や分量が不明なときは、それを要する判断だけを保留する。
- TeX・PDFのどちらか一方で開始できる。両方あれば式とマクロはTeX、ページと印字行番号はPDFで確認する。版の差が判断に影響するときは根拠にした版を示す。読めない記号や行番号を推測しない。

## 査読項目

| 番号 | 観点 | 確認すること |
| --- | --- | --- |
| 1 | 数学的内容の妥当性 | 仮定と結論を取り出し、推論の各段階、量化順序、定数・選択の依存、写像の定義が選択によらないこと、式変形の条件を追う。簡単な例や境界例で試し、「明らか」「同様に」の中身を補う。引用結果の仮定と各仮定の使用箇所を調べ、定義や引用を介した使用も確認してから未使用の仮定を挙げる。飛躍があれば直前に従うことと次に必要なことを示し、主張そのものの誤りと区別する。反例では全仮定と結論の破れを確かめる。仮定の追加・結論の弱化は変更前後と系・応用への影響を示す。 |
| 2 | 説明の重複 | 重なる二箇所を挙げ、それぞれの役割を読む。統合を勧めるなら、残す箇所と他方の短縮案を示す。 |
| 3 | 冗長さと不自然な言い回し | 過剰な強調、決まり文句、不自然な接続、直前の言い直しについて、読解を妨げる語句と、削った後に伝わる内容を示す。著者の語調と分野で自然な表現を保つ。 |
| 4 | 英文の代名詞 | it、this、these 等の指示先を前後から確かめ、候補が複数なら列挙する。意図が確かめられる範囲で既存の短い記号や対象名を使う。形式主語の it は除く。 |
| 5 | 記号の割り振り | 同じ文字が担う異なる意味、一つの対象の複数表記、添字・字体の揺れを調べ、競合する範囲と既存記号に衝突しない候補を示す。独立した証明での局所変数の再利用は、読み違いが生じる場合に扱う。 |
| 6 | 外部文献と内部参照 | 使用箇所・参照先・実際に使う主張を対応させる。外部の結果は、添付原典を優先し、本文を閲覧できた範囲で版・定理番号・仮定・結論を照合する。書誌情報のみなら著者が原典で照合すべき点を特定し、引用や定理番号を推測しない。 |
| 7 | 数式と地の文 | 散文で追いにくい量や添字の対応は既存記号の式と役割を示す一文で表す。論理記号が重なる式には文章化も検討する。前後で量化順序、添字範囲、依存関係を照合する。 |
| 8 | 英語の文体と語彙 | 英文が対象。John Milnor や Claude Viterbo の論文に見られる簡潔さを念頭に、正確な語、短い平叙文、証明の接続、冠詞・単複・時制・数式の句読点を点検する。原文・局所的な修正文・理由を示し、some と any、必要と十分、存在と一意性の区別を保つ。 |
| 9 | 未導入の用語・記号・主張 | 初出と最初の使用を追い、序論、節の共通仮定、既出の定義を照合する。標準用語と原稿固有の規約を区別する。欠落や循環があれば、使用箇所と、何をどこで定義・証明・引用すべきかを示す。 |
| 10 | 英文の長い主語と定理を主語とする文 | 英文が対象。定理名が主語の文などで根拠と帰結を追いにくい箇所を選び、なぜ明瞭になるかを説明し、候補を「原文」「修正文」の二列に並べる。元の主語が文脈に合う場合は残す。 |
| 11 | 全体の構成と主張の一致 | 提示された要旨・序論の主結果を本文の定理と対応させ、仮定・結論・記号を照合する。序論から結果の意義、先行研究との差、証明方針が伝わるかを読む。節の順序と論理的な依存をたどり、本筋を妨げる議論や付録に回せる部分を検討する。投稿先・分量の指定があれば削減・補足の判断に使う。 |

## 指摘の書き方

冒頭の一行に対象原稿と実際に確認した範囲を書く。指摘には同じ会話で続く番号（F1、F2、…）と項目番号を付ける。節・定理・式番号を優先し、短い原文引用、根拠、具体的な修正案または確認すべき点を示す。PDFならページと確認できた印字行番号、TeXのみならファイル名とラベル等、他の媒体なら同じ箇所を探せる位置を添える。

「要修正」（根拠のある誤り・証明の欠落）、「要確認」（資料・著者の意図・根拠が未確定）、「任意改善」（意味を保つ表現・構成案）の順に分け、各区分内では原稿順に並べる。一つの問題が複数項目に該当すればF番号は一つとし、項目番号を併記する。独立した証明の欠落は別件にする。同種の表現は代表例を詳しく扱い、残りは位置を列挙する。

修正文には必要な箇所だけを示し、仮定・結論と論理関係を保つ。TeXがあれば既存マクロを用いた修正文をコード表記にする。指摘が見つからなければ「該当なし」とする。末尾には次の三点を簡潔に記す。

- 項目ごとの結果（指摘あり・該当なし・未実施）。対象言語や資料の有無で適用できない場合はその理由を添える。
- 主要定理ごとの検証の深さ（全段階を確認・一部を確認・未確認）。原典や証明のどの部分を確認できなかったかも示す。
- 途中なら再開位置を特定し、次に点検する範囲と項目番号を示す。

## 依頼に応じて行う点検

- **類友法**　著者が挙げた一例から、何を問題とみなすかと除外条件を定める。候補ごとに該当箇所と根拠を確認する。
- **差分の再点検**　指定された変更前後の版を比較し、前回の指摘（同じ会話の回答も可）があれば、各F番号を変更後の箇所に対応させて「解消・未解決・確認不能」を記す。仮定・結論・記号の変更が後続の証明・系・応用・序論の主張に及ぼす影響も調べる。
